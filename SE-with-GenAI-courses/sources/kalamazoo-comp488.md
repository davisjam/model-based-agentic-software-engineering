## A. Explicit course content (quoted / cited)

### Identity
Kalamazoo College · Computer Science · COMP 488/490 (home page also styles it "CS 488/490") · syllabus header "Advanced Software Development"; home page and Geng Table 1 title "AI-Assisted Software Development" · Fall 2023 per Geng Table 1 (live pages undated; the linked instructor page shows Winter 2026) · instructor not named on the syllabus page itself (see §B) · undergraduate (senior-level; prerequisite COMP 210 Data Structures) · seminar/project format with a class Teams site.

### Stated learning objectives
As extracted from the syllabus (near-verbatim list): students will
1. "Broaden knowledge of software engineering and development topics"
2. "Further develop programming and teamwork skills through hands-on project work"
3. "Experiment with AI-assisted software development"
4. "Develop professional lifelong learning skills" through independent learning, topic research with presentations, and reflective documentation of progress.

Course description: "This course will focus on software development philosophies and practices. Topics will include traditional and agile software engineering approaches, common processes and tools, and the use of modern AI in software development."

### Organizing sequence
No public week-by-week schedule (the weekly schedule is an unreadable image on the instructor's page). The syllabus publishes a topic list rather than a sequence:
- Traditional/Agile software engineering approaches (SCRUM, UML, user stories, patterns, refactoring, testing, documentation)
- "Impact of Tools like ChatGPT, GitHub CoPilot, etc." (verbatim topic title)
- Project management (version control, continuous integration, tracking, teamwork, communication)
- Software architectures (client/server, web-based, mobile, distributed)
- Databases and design
- Usability and accessibility
- Contributing to existing projects
- Ethical and professional standards

### Assignments and project structure
- Growth Journal (individual) with weekly reflections — 45% ("Individual growth")
- Class contributions — 45%: presentations, discussions, collaborative software project work
- Topic/concept assessments — 10%
- Grading scale: 0–5 points per task (5 "Stands Out", 4 "A/Meets Expectations" … 0 "Not Done")
- Students research topics and present them to the class; presentations carry reflective responses.

### AI tools and agent frameworks used
ChatGPT and GitHub Copilot are named ("Impact of Tools like ChatGPT, GitHub CoPilot, etc."). Objective 3 commits students to "Experiment with AI-assisted software development." No agent frameworks, IDE integrations, or specific workflows are named in public materials.

### Readings
"Resources collected on class Teams site; no specific texts listed" — not publicly reachable.

### Treatment of: conventional SE activities
Extensive and central: agile/SCRUM, UML, user stories, refactoring, testing, documentation, version control, CI, architecture, databases, usability/accessibility, contributing to existing projects — the bulk of the topic list is conventional SE practice.

### Treatment of: human responsibility and judgment
Academic-integrity language only, verbatim: "Representing someone else's work as your own, in any form, constitutes academic dishonesty." Collaborative work must "clearly state who contributed to it," and students must acknowledge "any help from others or contributions from other sources." A specifically AI-directed responsibility policy: not evident in available materials.

### Treatment of: evaluation/verification of AI-produced work
Not evident in available materials. (Testing appears as a conventional SE topic; no public text connects it to verifying AI output.)

### Treatment of: persistent engineering knowledge beyond source code
The Growth Journal / weekly-reflection apparatus (45% of the grade) is reflective documentation of the student's own learning; "documentation" appears in the agile topic list. Engineering-knowledge persistence in the AI-collaboration sense: not evident in available materials.

### Treatment of: controls, constraints, governance, enforcement
Not evident in available materials, beyond the academic-integrity attribution requirements quoted above.

## B. Surveyor notes (interpretation, labeled)
- **Coverage gaps:** substantial. The public record is one syllabus page plus a home page; no schedule, no assignment specs, no readings. The Fall 2023 offering (the one Geng surveyed) is only reachable through the same live URL, which may have drifted; the instructor's linked page currently shows Winter 2026. Evidence strength: moderate-to-thin.
- **Instructor (inference):** the course home page's weekly-schedule link points into Alyce Brady's personal pages (`/abrady/`), so Alyce Brady is very likely the instructor; the syllabus page itself does not name one.
- **Organizing logic (interpretation):** a liberal-arts capstone-style advanced software development seminar — agile practice, teamwork, and reflective professional growth — into which experimenting with generative AI tools has been inserted as one strand ("Impact of Tools like ChatGPT, GitHub CoPilot, etc."). The AI strand is exploratory ("experiment with") rather than a disciplined methodology; nothing public indicates units on verification of AI output, prompting technique, or AI governance.
- **Classification reasoning (interpretation):** the syllabus body reads as a general SE course that includes (more than merely permits) AI tools → exclude, but borderline: the offering's title and objective 3 show deliberate AI emphasis whose depth is simply not observable in public materials. "Not observable" here, not "not taught."
