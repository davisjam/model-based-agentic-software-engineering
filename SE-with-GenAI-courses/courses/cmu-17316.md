# CMU 17-316/17-616 — AI Tools for Software Development

Fall 2025 (experimental first run) · Austin Henley, Andrew Begel · UG + grad cross-listed ·
[evidence](../sources/cmu-17316-ai-tools-for-software-development.md)

## What it teaches

The conventional SE lifecycle executed at one remove: "You will not write actual code in this
class. Instead, you will tell the large language model to do everything for you" (Begel). Seven
sequential team project phases — requirements engineering ("The Mom Test" interviews with real
humans "not LLMs", LLM-generated user stories scored with INVEST), development specifications,
frontend, backend, testing (TDD, CI), deployment (CD), final demo + postmortem. Every AI-mediated
phase is paired with a human-only 500-word reflection essay ("You should not use any AI... to
write this essay"), defended in class. Complete LLM chat logs are deliverables. Understanding is
enforced: "All adapted code from external sources requires full understanding demonstrated through
passing unit tests."

## How it is organized (interpretation)

A conventional-SE project course whose production mechanism is directing an LLM. Two design moves
stand out: (1) the systematic with-AI/without-AI contrast (human-first work products before AI
comparison; AI-free reflections) that makes the course partly a participatory field study of
AI-assisted SE — students "analyze the impact of AI tools on software productivity across
individuals, teams, and organizations"; (2) governance differentiated by artifact class — code may
be AI-produced nearly wholesale, while the metacognitive artifacts are walled off and orally
defended.
