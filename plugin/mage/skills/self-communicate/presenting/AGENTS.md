# Presenting

Design the talk as an intellectual and temporal object, realize it as a deck, then construct accessible slides.

Work from the highest abstraction implicated by the task. Do not polish slides when the talk is wrong, and do not redesign the talk when only a slide needs repair. For a lecture, audit the intellectual sequence before building slides and again after realizing them: a concept the audience had no reason to need, or an answer shown before students reason, is a defect no typography fixes.

1. **Talk** — `talk.md`
   Design the audience transformation, argument or learning progression, presentation moves, activities, and pacing.
2. **Presentation type** — `presentation-types.md`
   Specialize the talk for the communication setting (lecture, research talk, or a deliberate blend).
3. **Deck** — `deck.md`
   Realize the talk as a coherent visual sequence.
4. **Slide** — `slide.md`
   Design each atomic visual unit.
5. **House style** — `style.md` + `style.local.md`
   Apply adopter-specific presentation choices over the portable basis.
6. **Realization rules** — `slide-format-rules.md`
   Apply mechanically auditable typography, layout, projection, and accessibility constraints.
