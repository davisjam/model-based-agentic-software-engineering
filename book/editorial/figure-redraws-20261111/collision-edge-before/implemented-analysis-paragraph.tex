In DocAble, I adopted an interaction model borrowed from concurrency control's read/write conflict test~\citep{bernstein1981concurrency}. For each governance mechanism, the model records when it executes and which resources it reads or writes. Two mechanisms running at the same event have a potential conflict if they access the same resource and at least one writes it. For example, a post-commit code-style formatter writes a file that a subsequent checker reads. If the checker must inspect the formatted result, it must run afterward. The conflict graph identifies such interactions; the governance model records their resolutions.
